# v1.11.0-beta.1 — more useful at a glance

**Prepared beta, not yet published or flashed to a clock.** The last stable release
is v1.10.0. This beta keeps the same ESP-01S, 1 MB flash and single-file OTA path.

I wanted the time to stay the first thing you notice, with the weather close by.
The new **Time & weather** preset does that without making you wait for another
screen. The additional pages are optional; upgrading preserves your old choices.

![Actual OLED renders of the new beta screens](../../images/beta-oled-preview.png)

## New on the display

- Large time with a compact weather footer; clear/partly-clear nights use a moon.
- Outdoor temperature, feels-like temperature and humidity on a comfort page.
- Rain probability for the next three available hourly slots; six hours are cached
  and available in the web UI/API. This is hourly forecast data, not a rain radar.
- Two days of minimum/maximum temperature and maximum UV; wind speed and direction.
- Optional countdown to the next sunrise/sunset, using the clock's configured zone.
- °C/°F, km/h/m/s/mph, per-screen dwell times, immediate or dissolve transitions,
  and a night schedule that can dim the display instead of switching it off.
- Next, hold, resume and direct screen selection from the web UI or local API.

## New in the web interface and integrations

The compact basic settings stay together. Advanced display options expand only
when needed. Three presets provide a starting point: Clock only, Time & weather,
and Detailed weather. Import previews ordinary settings before Save; it neither
imports credentials nor immediately writes to the device. City search runs in the
browser and stages coordinates; timezone selection remains explicit.

The weather details include forecast data, units and reading age. A diagnostic
JSON download omits network identifiers, location, credentials and PINs.
Home Assistant can read the shared status endpoint or send one short external
card with automatic expiry. See the [guide and example](../HOME_ASSISTANT.md).
No MQTT library or sensor hardware has been added to the clock.

## Compatibility and resource budget

- Existing Config, WiFi, PIN and night records retain their offsets. A separate
  validated 32-byte feature record starts at EEPROM offset 432. Missing/corrupt
  feature settings default to the previous display behavior.
- `/api/weather` retains its fields and units. `/api/status` adds fields; all API
  temperatures stay °C and wind speeds stay km/h regardless of display preference.
- Weather bodies are capped at 3072 bytes; the parser has a separate allocation
  budget. Invalid responses preserve the last good reading and mark it stale.
- Build-time JS/CSS minification and a compact WiFi setup stylesheet recover flash
  space. The setup forms/protocols remain upstream WiFiManager; no runtime web
  framework, external font or filesystem asset upload is required.

## Installing the prepared beta

Use the single `.bin` from the local beta package in **Firmware** at `/update`.
Request the existing PIN on the clock and upload. Do not upload the source ZIP,
gallery or a filesystem image. No factory reset is required. After restarting,
select **Time & weather** and Save to enable the combined page.

Keep your settings export and the stable v1.10.0 binary for comparison or rollback.
Stable firmware ignores the extra feature record; do not reset EEPROM merely to
downgrade. External cards and display hold are transient and disappear on restart.

## Checks and remaining beta work

Host regressions cover storage isolation, field validation, retries, malformed and
oversized weather, date/offset handling, screen timing, night dimming and card
expiry including timer rollover. Chromium checks run against the actual minified
embedded page, including import/presets, units, controls, PIN and upload guards.
The real Adafruit_GFX rasterizer checks **72 scenarios in all four orientations
(288 renders)** with ASan/UBSan and zero implicit wraps or clipped text.

The binary is **477,600 bytes**, with **38,916 bytes** of static RAM and
**62,007 / 65,536 bytes** in the instruction region including cache. SHA-256 and
source identity are in the package's build information. Full measurements are recorded in [validation](../VALIDATION.md).
The GitHub workflow is updated but has not been run for this unpublished branch.
**OTA on the physical clock, OLED brightness/color appearance, captive-portal
provisioning, live Home Assistant integration and a 24-hour soak remain unverified.**
A read-only health check of the installed v1.10.0 is not beta hardware validation.
