# v1.11.1 — weather returns sooner after a failed first request

**2026-11-18**. A bug-fix release for **v1.11.0**. Settings, maintenance PIN and the
EEPROM layout are unchanged, so updating keeps your configuration. The web interface
is the one from 1.11.0.

## Fixed

- **No weather for a whole refresh interval after a failed first request** (#17).
  The clock asks Open-Meteo for the weather and gives up after 10 seconds. When the
  first request after a boot or a location change timed out, it retried three times
  within seconds and then waited a full refresh interval, 30 minutes by default.
  With no reading yet the weather screens are skipped, so only the time was shown
  for that long. Until it has a first reading the clock now tries again after one
  minute. Later refreshes are unchanged: the last reading stays on screen, marked
  `*`, and the next attempt comes after the refresh interval.

On a network where Open-Meteo answers slowly, a shorter **Refresh interval** in the
weather settings still helps: it also shortens the wait after a failed refresh.

## Install

- **From 1.11.0-beta.2 or newer:** open **Update**, keep _GitHub release_, choose
  **Stable**, select **v1.11.1 · Recommended**, show and enter the PIN, install.
  Reload the page after the restart.
- **From 1.10.0 or beta.1:** open `/update`, choose the downloaded
  `weather_clock-v1.11.1-<revision>.bin`, press **Show PIN on clock**, enter the six
  digits and upload.
- **From 1.9.x and first installation:** as for
  [v1.11.0](v1.11.0.md#install), with the 1.11.1 file.

## Validation

Pinned build: **478,944 bytes** firmware, **288 bytes** below the mutual-OTA limit
(the code grew by 16 bytes); **38,480 bytes** static RAM; **62,007 / 65,536**
instruction bytes including cache.

Passed: all host suites with ASan/UBSan, including a new case for an exhausted first
burst of weather requests that fails on the 1.11.0 sources; release ordering,
dictionary and catalog tests; 320 OLED renders; asset reproducibility; and in CI the
Chromium regression, ESLint and Ruff.

Hardware, 2026-11-18: a physical ESP-01S on 1.11.0 (22.6 hours uptime) was updated
over the air with the PIN-authenticated upload. It answered on 1.11.1 eight seconds
after the upload, kept every setting, and had a valid weather reading 18 seconds
after boot; the read-only device suite passed. The failed first request itself was
not reproduced on hardware: that path is covered by the host test. Details are in
[VALIDATION.md](../VALIDATION.md).
